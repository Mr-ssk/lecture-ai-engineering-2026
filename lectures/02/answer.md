## 宿題

- **取り組んだレベル**：基礎。既存 Notebook の設定を変更し、再学習と評価結果の比較を行った。
- **変えた設定やデータ**：`lora_r` を 16 から 8 に変更した。`lr = 0.0002`、`num_train_epochs = 20`、`lora_alpha = 32` は変えず、同じ学習データ・評価データを使用した。ランタイムのセッションを再起動して再学習した。
- **結果**：

  | 指標 | 元の設定（r=16） | 変更後（r=8） |
  |---|---:|---:|
  | `format_rate` | 100.00% | 100.00% |
  | `content_rate` | 90.48% | 85.71% |
  | 最終 Training Loss | 0.014032 | 0.013089 |
  | 学習時間 | 226秒 | 227秒 |
  | 学習可能パラメータ数 | 6,389,760 | 3,194,880 |

  `lora_r` を半分にすると、学習可能パラメータ数は約半分になった。一方、学習時間はほぼ変わらず、この環境では短縮効果を確認できなかった。`format_rate` は 100% を維持したが、`content_rate` は 4.76 ポイント低下した。r=8 では「課題の文字数に制限はありますか」に対し、確認を求めず PDF の提出形式を回答してしまった。

  r=8 の Training Loss は低かったものの、評価データに対する内容正答率は r=16 の方が高かった。Training Loss の低さが、実際の回答性能の高さを必ずしも意味しないことが分かった。ただし、評価は21問で、正答率の差は1問分にすぎないため、この結果だけで r=16 の優位性を一般化することはできない。また、`lora_alpha` を固定したため、LoRA のスケーリング係数 `alpha / r` は2から4に変化している点にも注意が必要である。
- **ファインチューニングが向く場面・向かない場面についての考察**：

  **向く場面：** JSON 形式などの決められた出力フォーマットや、回答時の判断ルールをモデルに定着させたい場合に有効だと考える。今回の演習では、少量の学習データでも形式遵守率を大幅に改善できた。特定業務の定型応答や、`needs_review` のような判断フラグを安定して出力させる用途に適している。

  **向かない場面：** 学習データに含まれない知識への回答や、頻繁に更新される情報を正確に回答させる用途では、ファインチューニング単独に限界がある。今回も、根拠のない質問に別の情報を回答する問題が残った。知識の正確性や最新性が重要な場合は、RAG など外部情報を参照する仕組みとの併用が適切だと考える。

  **総括：** ファインチューニングは、新しい知識を覚えさせること以上に、特定タスクで必要な出力形式や振る舞いを安定させる用途で効果がある。また、学習可能パラメータ数を減らしても学習時間が短くなるとは限らず、Training Loss だけでは性能を評価できない。実際の利用場面を想定した評価データで、形式と内容の両面を検証することが重要である。
